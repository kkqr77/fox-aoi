# Мой примерный график + Вишлист

Два инструмента на одном GitHub Pages репозитории. Данные хранятся в Firebase Realtime Database, всё работает в браузере без бэкенда.

- **[Расписание](https://kkqr77.github.io/fox-aoi/)** — календарь занятости и приём заявок на встречи
- **[Вишлист](https://kkqr77.github.io/fox-aoi/wishlist/)** — список желаний с бронированием подарков

---

## Расписание (`index.html`)

### Что умеет

- Показывает календарь на месяц с визуальной загрузкой каждого дня (мини-бар)
- Учитывает рабочий график 2/2
- День после ночной смены (смена 23:00–11:00) помечается красной точкой, но свободные окна и запись не блокируются
- Учитывает расписание сна (задаётся вручную по дням)
- Показывает свободные временны́е окна для выбранного дня
- Позволяет гостям оставлять заявки на конкретное время
- Страница открыта публично: пароль и отдельный экран входа не нужны
- Админ входит через Google кнопкой в шапке; вход сохраняется (`Auth.Persistence.LOCAL`) и переживает перезагрузку

### Настройки

В начале `index.html` можно изменить:

```js
var SLOT_STEP  = 1;                 // шаг слотов в часах
var START_HOUR = 0;                 // начало суток
var END_HOUR   = 24;                // конец суток
var DEFAULT_DURATION_MIN = 60;      // длительность встречи по умолчанию
var MIN_BOOKING_MINUTES  = 20;      // минимальная длительность заявки
var SUGGESTION_STEP_MIN  = 20;      // шаг предлагаемых вариантов времени
var BASE_TZ_OFFSET_MIN   = 5 * 60;  // часовой пояс календаря: Екатеринбург, UTC+5
```

### Панель администратора

Доступна после входа через Google — кнопка «Вход для админа» в шапке.

**Вкладка «Заявки»** — настройка графика 2/2, управление расписанием сна, список активных заявок: подтвердить / отклонить / редактировать.

**Вкладка «Архив»** — прошедшие события, доступно редактирование и удаление.

### Часовой пояс

Сетка, слоты и брони хранятся в настенном времени **Екатеринбурга (UTC+5, без перехода на летнее время)**. «Сейчас», «сегодня» и прошедшие слоты тоже считаются по Екатеринбургу, поэтому календарь выглядит одинаково у всех гостей.

Для гостей из других поясов:

- в шапке живая плашка «Время по Екатеринбургу: `HH:MM` · у вас `HH:MM` (`UTC±X`)»;
- в форме брони и редактирования показывается выбранный интервал в местном времени гостя, а если дата отличается — добавляется число и месяц.

Базовая зона задаётся константой `BASE_TZ_OFFSET_MIN = 5 * 60` в начале `index.html`.

## Вишлист (`wishlist/index.html`)

### Что умеет

- Карточки товаров с названием, описанием, ценой, картинкой (URL или смайл), категорией, тегами
- 5 уровней приоритета: «Очень хочу», «Было бы круто», «Низкий приоритет», «Спонтанное желание», «Мечта, когда-нибудь»
- Фильтрация по категории, приоритету, статусу (свободно / забронировано)
- Сортировка по приоритету (внутри — по цене), цене, новизне
- Бронирование подарков гостями: имя, подтверждение намерения, комментарий, опциональная дата вручения, анонимный режим
- Владелец вишлиста не видит, кто забронировал подарок (сюрприз сохраняется)
- Другие гости видят статус занятости и имя бронирующего (если бронь не анонимная)
- Транзакционная запись брони — двойное бронирование невозможно
- Длинные описания сворачиваются с кнопкой «Читать далее»
- Публичный доступ без пароля; добавлять и редактировать товары может только админ после входа через Google

### Поля карточки товара

| Поле | Описание |
|---|---|
| `name` | Название товара (обязательно) |
| `description` | Описание (до 500 символов) |
| `url` | Ссылка на магазин |
| `price` | Цена |
| `currency` | Валюта (₽ / $ / € / ¥) |
| `imageUrl` | URL картинки или смайл (например `🎮`) |
| `category` | Категория (Игры, Техника, Аниме…) |
| `priority` | Приоритет 1–5 |
| `tags` | Теги через запятую |

### Поля брони

| Поле | Описание |
|---|---|
| `name` | Имя бронирующего (для анонимной брони сохраняется как `Аноним`) |
| `comment` | Комментарий (необязательно) |
| `giftDate` | Примерная дата вручения (необязательно) |
| `isAnonymous` | Скрыть имя от других гостей |

## Быстрый старт

1. Создайте проект в [Firebase Console](https://console.firebase.google.com/)
2. Включите **Authentication** → Google (нужен только для входа админа)
3. Включите **Realtime Database**, настройте правила (см. ниже)
4. Замените Firebase-конфиг в обоих файлах (`index.html` и `wishlist/index.html`):

```js
firebase.initializeApp({
  apiKey: "...",
  authDomain: "...",
  databaseURL: "...",
  projectId: "...",
  storageBucket: "...",
  messagingSenderId: "...",
  appId: "..."
});
```

5. Замените константу:

```js
var ADMIN_UID = 'uid_вашего_google_аккаунта';  // Firebase UID админа (Authentication → Users)
```

6. В **Authentication → Settings → Authorized domains** добавьте домен, на котором открывается сайт (например `kkqr77.github.io`), иначе вход через Google не откроется.

## Правила Firebase Realtime Database

Правила задаются в **Realtime Database → Rules** в Firebase Console и в репозиторий не коммитятся. Модель доступа:

- **читать** `config`, `shiftOverrides`, `sleep`, `bookings`, `slotLocks`, `wishlist/items` и `wishlist/reservations` может любой — страницы публичные;
- **создавать** заявку в `bookings` и бронь в `wishlist/reservations` может любой, но только новую и только со статусом `pending`;
- свежую pending-заявку можно удалить в течение 2 минут — это нужно для отката, если слот заняли в момент бронирования;
- **менять и удалять** заявки, брони, товары, конфиг и сон может только админ — по `uid`, а не по email;
- `slotLocks` открыт на запись всем: это технический узел для атомарного бронирования, без него гости не смогут занимать слоты;
- `bookingMeta` (IP, user-agent и т.п.) читает только админ;
- `duo/*` (страница «Общее время») — только админ, без публичного доступа.

> Админ определяется по `ADMIN_UID` из кода. Если смените Google-аккаунт — обновите `ADMIN_UID` и в правилах.

## Структура данных

### `bookings/{id}`

| Поле | Тип | Описание |
|---|---|---|
| `date` | string | Дата начала `YYYY-MM-DD` |
| `startTime` | string | Время начала `HH:MM` |
| `endTime` | string | Время окончания `HH:MM` |
| `endDate` | string | Дата окончания (если переходит через полночь) |
| `name` | string | Имя гостя |
| `activity` | string | Чем хотят заняться |
| `isAnonymous` | boolean | Скрыть детали от других |
| `status` | string | `pending` / `confirmed` |
| `ts` | number | Unix timestamp создания |

> У старых заявок может остаться поле `_meta` (IP/UA). Новые заявки пишут его в `bookingMeta/{id}`, который читает только админ. Старые `_meta` можно удалить вручную в Firebase Console.

### `bookingMeta/{bookingId}`

Служебные данные заявки. Читает только админ; гость может создать запись после создания брони.

| Поле | Тип | Описание |
|---|---|---|
| `ip` | string | IP гостя |
| `ua` | string | User-Agent |
| `platform` | string | Платформа |
| `lang` | string | Язык браузера |
| `screen` | string | Размер экрана |
| `tz` | string | Часовой пояс |

### `slotLocks/{YYYY-MM-DD}/{bookingId}`

Технический узел для атомарного бронирования: не даёт двум гостям занять одно и то же время. Создаётся и снимается кодом вместе с бронью, вручную не редактируется.

| Поле | Тип | Описание |
|---|---|---|
| `start` | number | Начало интервала в минутах от 00:00 |
| `end` | number | Конец интервала в минутах (1440 = полночь) |

### `config`

| Поле | Тип | Описание |
|---|---|---|
| `referenceDate` | string | Дата первой рабочей смены для расчёта графика 2/2 |

### `sleep/{YYYY-MM-DD}`

| Поле | Тип | Описание |
|---|---|---|
| `start` | string | Время отхода ко сну `HH:MM` |
| `end` | string | Время подъёма `HH:MM` |

### `wishlist/items/{id}`

| Поле | Тип | Описание |
|---|---|---|
| `name` | string | Название товара |
| `description` | string | Описание |
| `url` | string | Ссылка на магазин |
| `price` | number | Цена |
| `currency` | string | Валюта |
| `imageUrl` | string | URL картинки или смайл |
| `category` | string | Категория |
| `priority` | number | Приоритет 1–5 |
| `tags` | string | Теги через запятую |
| `ts` | number | Unix timestamp создания |

### `wishlist/reservations/{itemId}`

| Поле | Тип | Описание |
|---|---|---|
| `name` | string | Имя бронирующего |
| `comment` | string | Комментарий |
| `giftDate` | string | Примерная дата вручения `YYYY-MM-DD` |
| `isAnonymous` | boolean | Анонимная бронь |
| `ts` | number | Unix timestamp создания |
